# vertical-research

**산업별(버티컬) 영업 대상 업체를 AI가 조사하고, 점수를 매기고, 한국어 보고서로 정리해 주는 Claude Code 플러그인입니다.**

예를 들어 "건설현장 출입통제"라고 입력하면 다음 결과를 만들어 줍니다.

- 이 시장에서 경쟁하는 업체와 우리 제품의 차별점
- 우리 제품을 탑재하거나 함께 판매할 수 있는 후보 업체 목록
- 업체별 평가 점수와 그 근거(출처 링크 포함)
- 영업 담당자가 바로 읽을 수 있는 한국어 보고서

B2B 제품(엔진, SDK, 부품 등)을 자기 제품에 넣어 줄 파트너사를 찾는 영업 리서치에 맞춰 만들었습니다.

## 어떻게 동작하나요?

일을 나눠 맡는 AI 에이전트 다섯 개가 순서대로 일합니다. 각 단계 사이에는 **검사 스크립트**가 있어서, 형식이 틀리거나 근거가 빠진 결과는 다음 단계로 넘어가지 못합니다.

```
① 계획      planner       조사할 범위를 3~6개 단위로 나눕니다
② 조사      researcher    단위별로 동시에 웹을 조사합니다 (여러 개가 병렬로 일함)
   ✔ 검사               빠진 항목이나 출처 없는 근거가 있으면 되돌려 보냅니다
③ 검증      verifier      출처를 다시 열어 조사 내용이 맞는지 따로 확인합니다
④ 채점      (스크립트)     제외 기준 적용, 점수 합산, 순위 매기기
⑤ 작성      writer        한국어 보고서를 씁니다
⑥ 한국어 심사 ko-reviewer   어색한 번역투나 AI 말투를 찾아냅니다
   ✔ 검사               심각한 문제가 남아 있으면 ⑤로 돌아가 다시 씁니다 (최대 2회)
```

### 에이전트별 역할

| 에이전트 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **planner** (계획) | 조사 단위, 질문, 검색어, 참고할 출처를 정합니다 | 직접 업체를 조사하지 않습니다 |
| **researcher** (조사) | 업체 홈페이지와 공개 자료를 보고 항목별 근거를 모읍니다 | 확인하지 못한 내용을 추측으로 채우지 않습니다 |
| **verifier** (검증) | 출처를 직접 다시 열어 근거가 맞는지 확인하고 바로잡습니다 | 조사자의 메모를 보지 않습니다 (선입견 방지) |
| **writer** (작성) | 조사 결과를 영업용 한국어 보고서로 정리합니다 | 새 사실을 추가하거나 점수를 바꾸지 않습니다 |
| **ko-reviewer** (한국어 심사) | 번역투, 비문, AI 상투어를 심각도별로 지적합니다 | 글을 직접 고치지 않습니다 (작성자가 고침) |

### 이렇게 만든 이유

- **점수는 스크립트가 계산합니다.** AI는 항목마다 "상/중/하/확인불가"와 근거만 냅니다. 합산과 순위는 스크립트가 하므로 계산 실수가 없습니다.
- **모르면 "확인불가"로 둡니다.** 확인하지 못한 항목은 0점으로 처리하고, 이런 항목이 2개 이상인 업체에는 `근거부족` 표시를 붙입니다.
- **쓴 사람과 검사하는 사람이 다릅니다.** 조사자와 검증자, 작성자와 심사자를 나눴습니다. 자기 결과를 스스로 채점하면 관대해지기 쉽기 때문입니다.
- **사람은 표시된 업체만 다시 보면 됩니다.** 순위 경계에 있는 업체, 근거가 부족한 업체, 검증되지 않은 업체에 표시가 붙습니다.

조사를 나눠 병렬로 진행하는 구조는 Anthropic의 `deep-research` 예제 스킬을, 역할을 나누고 스크립트로 검사하는 방식은 [iterate-solo](https://github.com/MMSS9402/iterate-solo)를 참고했습니다.

## 한 업체가 여러 버티컬 사업을 할 때

SI 업체 한 곳이 건설현장 근태, 스마트빌딩 출입통제, 공장 보안을 모두 하는 경우가 흔합니다. 버티컬마다 따로 조사하면 같은 업체에 제안서가 두 번 가거나, 다른 사업부의 실적이 근거로 섞일 수 있습니다. 이 플러그인은 다음 규칙으로 이 문제를 막습니다.

| 규칙 | 설명 |
|---|---|
| **업체 1곳 = 제안서 1건** | 여러 버티컬에서 발견된 업체는 하나로 묶습니다. 점수가 가장 높은 버티컬을 **제안 버티컬**로 정하고, 나머지 버티컬은 같은 제안서에 확장 제안으로 넣습니다 |
| **회사 공통 항목과 버티컬 항목 구분** | 매출, 임직원 수처럼 회사 전체에 하나뿐인 값은 한 번 조사해 다시 씁니다. 자체 플랫폼, 고객 사례처럼 사업부마다 다른 값은 버티컬마다 따로 봅니다 |
| **근거는 해당 사업부 것만** | 건설 버티컬 점수에 그 회사 스마트빌딩 사업부의 고객 사례를 쓰지 않습니다. 근거마다 어느 사업부 것인지 적고, 검증자가 이를 확인합니다 |
| **제외 기준은 회사 단위** | 한 사업부라도 얼굴인식 엔진을 직접 팔면 경쟁사로 보고, 모든 버티컬에서 제외합니다 |
| **전체 업체 명부** | 실행할 때마다 `research/_registry/`의 명부가 갱신됩니다. 팀 목표(예: 40곳)는 이 명부의 업체 수로 셉니다 |

## 설치

### 방법 1. Claude Code (터미널 또는 Claude 데스크탑의 Code 탭)

Claude Code 입력창에 아래 두 줄을 차례로 입력합니다.

```
/plugin marketplace add MMSS9402/vertical-research
/plugin install vertical-research@vertical-research
```

설치한 뒤에는 **새 세션을 열어야** 명령이 나타납니다. Claude 데스크탑 앱의 Code 탭도 같은 Claude Code이므로 같은 방법으로 설치합니다.

**필요한 것**
- Python 3.8 이상 (`python3` 또는 `python` 명령이 동작해야 합니다)
- 웹 검색 도구(WebSearch, WebFetch)를 쓸 수 있는 환경

**업데이트**

```
/plugin marketplace update vertical-research
/plugin update vertical-research@vertical-research
```

### 방법 2. Claude 데스크탑 채팅 또는 claude.ai (간이판)

일반 채팅 화면에서는 여러 에이전트를 동시에 띄울 수 없습니다. 그래서 같은 절차를 AI 하나가 순서대로 진행하는 **간이판 스킬**을 따로 제공합니다.

1. 이 저장소의 [`dist/vertical-research-lite.zip`](dist/vertical-research-lite.zip) 파일을 내려받습니다.
2. Claude 데스크탑(또는 claude.ai)에서 **설정 → 기능(Capabilities) → Skills**로 가서 zip 파일을 업로드합니다. 코드 실행 기능이 켜져 있어야 합니다.
3. 채팅에 설정 파일을 올리고 "건설현장 출입통제 버티컬 업체 조사해 줘"처럼 요청합니다.

간이판은 병렬 조사가 없고 검증도 같은 AI가 하므로, 플러그인보다 느리고 덜 엄격합니다. 메뉴 이름은 앱 버전에 따라 조금 다를 수 있습니다.

## 사용법

### 1단계. 설정 파일 만들기 (폴더당 한 번)

```
/vertical-research:init
```

현재 폴더에서 제품 사양 문서와 평가 기준을 찾아 `.claude/vertical-research.config.md`를 만듭니다. 찾지 못한 값은 `TODO`로 남기고 질문합니다.

### 2단계. 조사 실행

```
/vertical-research:run "건설현장 출입통제"
/vertical-research:run "카지노 VIP 인식" APAC 30
```

| 입력 | 의미 | 생략하면 |
|---|---|---|
| 첫 번째 (따옴표) | 조사할 버티컬 | 생략할 수 없음 |
| 두 번째 | 조사 지역 | 설정 파일의 기본 지역 |
| 마지막 숫자 | 최종 후보 수 | 설정 파일의 `top_n` |

버티컬을 바꿔 여러 번 실행하면 업체 명부가 계속 이어집니다.

## 결과물

결과는 `research/<버티컬>-<날짜>/` 폴더에 저장됩니다.

| 파일 | 내용 |
|---|---|
| `report.md` | **한국어 보고서.** 요약, 경쟁 구도, 주요 업체, 후보 순위, 업체별 제안 포인트, 여러 버티컬에 걸친 업체, 다시 볼 업체 |
| `candidates.csv` | 순위, 점수, 항목별 등급, 검토 표시, 제안 버티컬, 제외 사유 (Excel에서 바로 열립니다) |
| `evidence.md` | 업체별 항목 근거, 근거 사업부, 출처 링크 |
| `plan.md`, `notes/`, `records/`, `verify/` | 단계별 중간 결과 |
| `ko_review.json`, `run_log.md` | 한국어 심사 결과, 실행 기록 |

여러 버티컬을 합친 **전체 업체 명부**는 `research/_registry/`에 있습니다.

| 파일 | 내용 |
|---|---|
| `companies.csv` | 업체 1곳 = 1줄. 제안 버티컬, 점수, 함께 제안할 버티컬, 제외 여부 |
| `summary.md` | 전체 업체 수, 제안 대상 수, 여러 버티컬에 걸친 업체 목록 |
| `company_facts.json` | 이미 확인한 회사 공통 정보 (다음 조사에서 다시 씁니다) |

### 검토 표시의 뜻

| 표시 | 뜻 | 할 일 |
|---|---|---|
| `근거부족` | 확인하지 못한 항목이 2개 이상입니다 | 빠진 정보를 직접 확인합니다 |
| `경계` | 순위가 최종 후보 기준선 근처(±5위)입니다 | 포함할지 사람이 판단합니다 |
| `미검증` | 검증 단계를 거치지 않았습니다 | 출처를 직접 확인합니다 |
| `타버티컬제안` | 다른 버티컬에서 점수가 더 높습니다 | 그 버티컬 기준으로 제안서 1건만 씁니다 |
| `타버티컬KO` | 다른 버티컬 조사에서 제외 기준에 걸렸습니다 | 제안 대상에서 뺍니다 |
| `회사공통 불일치` | 매출 등 회사 공통 값이 조사마다 다릅니다 | 어느 값이 맞는지 확인합니다 |

## 설정 파일

[`examples/vertical-research.config.md`](examples/vertical-research.config.md)를 복사해 고쳐 씁니다. 사람이 읽는 제품 요약과, 스크립트가 읽는 `json vr-config` 블록으로 이루어져 있습니다.

| 항목 | 의미 |
|---|---|
| `product_name`, `product_spec` | 제안할 제품 이름과 제품 사양 문서 경로 |
| `top_n`, `regions`, `output_dir` | 최종 후보 수, 기본 조사 지역, 결과 폴더 |
| `knockout` | 제외 기준 (예: 직접 경쟁사, 단순 유통업체) |
| `scoring` | 평가 항목과 배점. 항목마다 `scope`를 `company`(회사 공통) 또는 `vertical`(버티컬별)로 지정합니다 |
| `contact_roles` | 접촉할 담당자 직책의 우선순위 |
| `public_terms` | 웹 검색어에 써도 되는 공개 용어 |
| `confidential` | 절대 외부로 보내면 안 되는 내용 |

> ⚠️ **주의:** 설정 파일과 제품 사양 문서에는 사내 정보가 들어갑니다. 공개 저장소에 올리지 마세요. 이 저장소의 `.gitignore`도 설정 파일을 제외하도록 되어 있습니다.

## 자주 묻는 질문

**Q. 점수를 AI가 매기면 믿을 수 있나요?**
AI는 항목별 등급과 근거만 정하고, 검증 에이전트가 출처를 다시 확인합니다. 근거가 없으면 "확인불가"로 0점 처리합니다. 다만 최종 판단은 사람이 해야 합니다. 검토 표시가 붙은 업체부터 보시면 됩니다.

**Q. 개인 정보도 수집하나요?**
수집하지 않습니다. 담당자는 직책(예: Head of Product)과 그 직책을 확인한 공개 페이지 주소까지만 기록합니다.

**Q. 사내 자료가 외부로 나가지는 않나요?**
에이전트는 웹 검색어에 설정의 `public_terms`와 일반 산업 용어만 씁니다. `confidential` 항목과 제품 사양 원문은 검색어에 넣지 않도록 규칙으로 막았습니다. 그래도 회사의 AI 사용 정책은 꼭 확인해 주세요.

**Q. 한 번 실행하는 데 얼마나 걸리나요?**
버티컬 범위와 후보 수에 따라 다르지만, 여러 에이전트가 웹을 많이 조사하므로 수십 분이 걸릴 수 있고 토큰도 많이 씁니다. 처음에는 `top_n`을 작게(예: 10) 잡아 시험해 보시길 권합니다.

## 한계

- 웹에 공개된 정보만 다룹니다. 비상장 회사의 매출과 임직원 수는 "확인불가"가 많이 나옵니다.
- 검증 에이전트가 확인하는 것은 "출처에 그렇게 적혀 있다"까지입니다. 출처 자체가 틀렸을 수 있습니다.
- 최종 후보 목록은 초안입니다. 제안할지, 누구에게 연락할지는 사람이 정합니다.

## 저장소 구조

```
.claude-plugin/        플러그인·마켓플레이스 정보

scripts/gate.py        검사·채점·업체 명부 스크립트
scripts/build_desktop_skill.py   간이판 zip 만들기
desktop/SKILL.md       간이판 스킬 본문
examples/              설정 예시 (가상 제품)
tests/                 검사 스크립트 테스트
```

### 개발자용

```
python -m unittest discover -s tests       # 검사 스크립트 테스트
python scripts/build_desktop_skill.py      # 간이판 zip 다시 만들기
```

에이전트나 기준 문서를 고친 뒤에는 간이판 zip도 다시 만들어 함께 올려 주세요.
